# На какой стадии находится идея

Четыре независимых оси. Для каждой — где проект сейчас, по чему это видно,
и что считается переходом на следующую ступень.

## 1. Идея (что утверждается)

**Тезис.** Долгий диалог с ИИ нельзя вести в ленте: контекст тащит всё
предыдущее, «Да» выглядит как подтверждение факта, параллельные темы
сливаются. Нужна плоскость с адресуемыми записями, канон, который ставит
только человек, и машина, которая ходит по id.

**Стадия: сформулирована и впервые проверена на собственном корпусе.**
Корпус — один диалог на 344 тыс. строк, где 74 из 81 хода пользователя —
«Да», «Продолжение» и их варианты. Это наглядный аргумент: лента кормит сама себя.
В v2.1 корпус прогнан через стол целиком (`docs/CORPUS.md`): 95% текста
лежит в блок-цитатах, 32 035 нумерованных секций, из них 803 с ячейкой в
заголовке. То есть идея «ячейка ≠ как первичная грамматика» на своём же
корпусе даёт 2,5% секций; остальное — обычные наблюдения, код и ярлыки.
Эксперимент один, автор один, разметка — модели, не люди.

**Ближайшие аналоги** (идея не изолирована, но комбинация своя):
- Zettelkasten / ADR (architecture decision records): атомарные записи, явное
  решение vs обсуждение. Нет машинного слоя.
- Курирование памяти агентов (MemGPT/Letta, «memory blocks»): есть канон, но
  его ставит модель, не человек.
- Триплеты RDF / knowledge graph: есть `pred rel obj`, нет цикла raw→canon с
  человеком в контуре.
- Разметка с человеком в контуре (Prodigy, Label Studio): raw→accepted
  пачкой — очень близко, но без алгебры множеств и без «языка, растущего из
  журнала».

**Что своё:** (а) `≠` как первичная грамматика (различения важнее
определений), (б) запрет MUL / только единичные рёбра, (в) спецификация языка
как производная журнала, (г) приборы, которые сами сажают вопросы.

**Переход на следующую ступень:** второй корпус от другого человека и
измеримый выигрыш (например: доля «Да»-ходов до/после, число ячеек на 1000
строк, время до первого канона).

## 2. Методы (как это делается)

| Метод | Стадия | Замечание |
|---|---|---|
| Нарезка ленты + эвристический классификатор | измерен | v1: по пустым строкам, 7 правил, без оценки; v2.1: цитаты, секции, ярлык+блок, классы code/label; точность типа на 200 абзацах с разметкой трёх судей-моделей: 0,30 → 0,78 (0,94 на единогласных); ячейки: точность 1,0 → 0,83, полнота 0,5 → 0,63 (`docs/CORPUS.md`) |
| Ячейка `pred ≠ obj` из заголовка | рабочий, узкий | в v2.1 `≠ → ⊂ = vs`; на корпусе 2,5% секций несут ячейку в заголовке — грамматика покрывает малую часть материала |
| Алгебра множеств над id | рабочий | в v1 один оператор; в v2.1 полное выражение со скобками, фильтры, `turn:n`; семантика `NEQ`/`JUNK` возвращена к v1 после ревью |
| Приборы (заряд, перекос, рёбра, мусор) | эвристики | пороги те же, что в v1, но как данные; вычтенные строки исключены из массы |
| GAP → SETTLE → GAP | рабочий | замкнутый контур; в v2.1 закрытый GAP снова открывается, если правило ожило |
| SPEC из журнала | рабочий | живые и откаченные события считаются отдельно; журнал уплотняется после 5000 событий |
| NEXT | рабочий | правила над формой книги (открытый ярлык C, dormant signpost, contradicts, цепочки) |
| PACKET между сессиями | сохранён | письма из v1 читаются и видны в `WHY`; глаголов для новых писем нет |
| Откат | рабочий | `UNDO` ходом, `REPAIR id` |
| Роли | дисциплина | `ACTOR machine` запрещает канон, но переключатель в тех же руках |
| Слияние столов | рабочий | `MERGE`/`DIFFBOOK` с политикой «канон побеждает» |

## 3. Концептуальная разработка

**Стадия: ранняя, метафорическая.** Термины — ромб, улитка/раковина,
заряд конденсатора, морфизм, MUL — используются как образы, определений нет.
`LANG.md` на 40 строк — это манифест, не спецификация. Например:

- «MATRIX = GRID, умножение запрещено: это склейка кластеров» — утверждение
  понятно интуитивно, но что такое кластер формально (A/B/C/D — проекты? слои?
  роли?) не сказано нигде.
- «ступень = закон» (THEORY.md упоминается в архиве, в репозитории его нет).
- Слой 1 / слой 2 (`layer`) заведён в схеме, но смысла ему не назначено: его
  читает только фильтр множеств `layer:1`, ни одно правило приборов или NEXT
  на него не смотрит.

**Что нужно для перехода:** одностраничная формальная модель — типы, статусы,
допустимые переходы статусов (кто может: человек/машина), инварианты (session
никогда не canon; canon не удаляется, только REPAIR), и словарь отношений
рёбер с направлением. В v2 это начато: `src/engine/types.ts` + `docs/V2.md`.

## 4. Техническая разработка

**Стадия: лабораторный прототип (TRL 3–4 по аналогии).** В v1 он работал
только в той песочнице, где был собран, собирался с ошибками и не имел
тестов; в v2.1 это переносимый прототип с тестами и встречным ревью, но всё
ещё одиночный стол без второго пользователя и второго корпуса.

| Критерий | v1 | v2.1 (эта ветка) |
|---|---|---|
| Запускается вне песочницы Grok | нет | да (браузер, IndexedDB; SSR на Vercel) |
| `npm ci` / typecheck / build | красные | зелёные |
| Тесты | 0 | 29 сценариев движка + 13 хранилища, включая баги v1 и находки двух кругов ревью |
| Источников истины | 3 (sqlite, zustand-rows, zustand-plane) | 1 (Book в движке) |
| Откат | REPAIR по эвристике | UNDO ходом + REPAIR id |
| Правила хода | константы | правила над формой |
| Импорт | нет | нормализация любого входа, предупреждения, слияние |
| Корпус 4,7 МБ | не сажался (абзацы по 140 КБ) | 32 891 запись: нарезка 0,7 с, посадка в стол 1,7 с, FILL 0,03 с, UNDO 0,2 с (Node 22; до правки индекса посадка шла 35 с); ~630 ячеек внутри тел секций пока не всплывают в заголовки |
| Встречное ревью | нет | 75 находок, исправлены; аудит сам прошёл errata |
| Документация | `info` | README + AUDIT (с errata) + STAGE + V2 + PROTOCOL + CORPUS |

**Что отделяет от «альфы»:** несколько пользователей на одном столе (нужен
сервер и аккаунты — §0.5 AGENTS.md это допускает по явному запросу),
измеримая точность классификатора, экспорт в формат, который читают другие
инструменты (CSV/RDF).

## 5. Одной строкой

Идея — зрелая гипотеза, впервые измеренная на собственном корпусе и давшая
скромную цифру (ячейки — 2,5% секций); методы — рабочие эвристики с
измеренной точностью; концепция — манифест, у которого в v2.1 появился
исполняемый контракт (статусы, роли, множества, нормализация), но не
формальная модель; техника — прототип, который в v1 нельзя было запустить
нигде, кроме места рождения, а в v2.1 можно запустить где угодно и который
выдержал встречное ревью.
